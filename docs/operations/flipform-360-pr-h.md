# PR-H — Enterprise data foundation
Base 6d51f0e28158a72e12080f9712618d05391892ef; PR-G #665 merged.
## Scope
Pure, offline adapter contracts for orders, inventory snapshots, CRM opportunities, receivables/payables. ERP/CRM input is synthetic canonical fixture data, not a vendor-specific API implementation. No raw field maps from clients, arbitrary URLs or dynamic adapters. Strict grants by tenant/provider/account/connection/kind, sandbox or fixture only, trusted observation receipt bound to report, exact minor monetary units for BRL/USD/EUR, timestamps, duplicate rejection. Preserve order value, CRM expected value and receivable face value separately; none is recognized revenue or settled cash. Unknown Asaas statuses remain unknown; cashRealized always null. Inventory only non-negative whole units; fractional or negative balances need explicit future contracts. No PII fields returned (opaque identifiers still require access controls). Source selection takes an explicit trusted authoritative connection and rejects mixed tenants; no automatic cross-system joins or double counting. It does not authenticate the actor or prove completeness.
## Concrete read plans
- Asaas sandbox only: fixed GET /v3/payments, due-date window <=31 days, 100/page, max offset 9900, bound cursor, no repeated polling. Official https://docs.asaas.com/reference/listar-cobrancas ; provider advises webhooks for tracking changes; this module is for point-in-time reconciliation only. A due-date filter is not a settlement-period report. Verify actual response pagination, account identity and currency in sandbox before enabling. Existing PR-B sandbox discovery and PR-C fixture persistence remain untouched. No real Asaas access or webhook in this PR.
- Banco Central SGS: fixed public HTTPS query for series 432 (Copom target Selic, percent/year, daily) and 433 (IPCA monthly percentage variation). Max 366 days, provider period preserved, possible future-dated observations flagged, not a forecast or firm-specific data. Source attribution BCB/SGS and IBGE for IPCA; review ODbL and applicable data terms before redistribution. Reference https://dadosabertos.bcb.gov.br/en/dataset/432-taxa-de-juros---meta-selic-definida-pelo-copom/resource/2cb57a62-49de-405d-938b-482051a6e166 ; https://www3.bcb.gov.br/sgspub/ ; official Asaas and BCB references consulted, no endpoint called with credentials.
## Operational blockers
No OAuth, credentials, network transport, route, UI, migration, persistence, cron, provider write, lead modifications, production flag or new dependencies. Before actual use: choose ERP/CRM vendors, obtain permissions and official API docs, validate token/account/resource binding and trusted grants, isolate sandbox/live, implement MFA/roles/consent, vault, quotas, fixed egress, response size limits, pagination stability, idempotent reconciliation, revision conflict handling, verified coverage, privacy/retention and authorization, source-priority policy. Receipts are trusted backend context, not cryptographic proof. The current UniversalDataRecord schema is finance-fixture-specific; do not force all kinds into it. A separate reviewed additive schema or domain storage is required for real persistence. No actual sales/financial totals may be exposed until authoritative source coverage and reconciliation are tested.
