## Scope
Pure read-plan and normalization for daily campaign reports, single account, fixed GET host/path, 30-day window, 100 rows/page. No fetch, key registration, spend, publication, credentials, schema, API route, UI, job, activation or change to PR-D/E. TikTok v2.0 uses advertiser_ids with exactly one ID and local timezone, numeric page cursor. OpenAI uses its separate ad-account-scoped Advertiser API key, not the model API key, account check GET /ad_account and daily Insights; after uses last_id. Missing values remain null. Monetary values use integer micros; no currency conversion or mixing. Reports never imply CRM contracts/revenue; CPL/CPA/ROAS remain null. Reject duplicate rows and ambiguous cross-tenant grants. Cursor bound to account, connection, currency/timezone and date window; no arbitrary next URL.
## Limits
Trust boundaries: grants, verified account receipt and cursor must be created and kept by a future authenticated server transport. These pure functions do not authenticate the caller or prove a token belongs to a tenant. OpenAI verify response must come from the exact credential used in the later report; TikTok must verify account access/currency/timezone with official account API. Verify MFA, active Premium Pro, explicit consent and authorization, account uniqueness, secret vault, egress guard, TLS/DNS, timeout/body bounds, retries/quotas, per-connection limits, signed or stored cursor and max pages before enabling real access. TikTok synchronous report may truncate, so page exhaustion does not certify coverage; no real report can be presented as complete before reconciliation. OpenAI result freshness and reporting limits require validation. Do not expose raw tokens, URLs with secrets or customer data. No writes, no advertising budget, no automatic optimization, no changes to existing workflows.
