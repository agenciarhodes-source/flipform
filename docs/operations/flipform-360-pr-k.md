Dedicated platform phone_number_id disjoint from commercial assets. Synthetic routing contract requires already verified signature; actual raw signature verification is not implemented here. Fixture only, default unavailable unless fixture config explicitly enabled; no routes or traffic.
Authorization simulation: exact canonical sender digits, dedicated asset, active consented binding, phone verification, active owner membership/tenant, explicit executive permission and permitted domains. Phone alone is never authentication; explicit company selection through separately authenticated portal and recent MFA, bound to session, sender, asset, user, binding and tenant. Same phone linked to distinct users or duplicate tenant bindings fails closed. No list of candidate companies in chat. 15-minute max portal proof/MFA and 5-minute event freshness are conservative fixture defaults, not operational SLAs. Replay list is illustrative, not durable atomic claim. Commands exact allowlist only; no audio, free-form AI, mutation, publication or external calls. All trusted inputs must come from verified server state; never accept from webhook JSON or client/LLM. PR-J briefing invoked through dependency injection for offline tests, domain checks, no actual dispatch/outbox or CRM writes.
