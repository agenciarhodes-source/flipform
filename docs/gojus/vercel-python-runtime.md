# GoJus — runtime Python nativo da Vercel

Substitui transporte base64 por manifesto pequeno com URLs R2 pré-assinadas pelo backend. A função Python GET dos originais e PUT do PDF de apresentação no prefixo flip-pdf-temp/<tenant>/<uuid>.pdf, sem receber credenciais do R2 ou banco. Retorna apenas tamanho, páginas e SHA-256 calculado pelo worker. Backend confirma tamanho e tipo por HEAD e recalcula o SHA-256 via GET privado em streaming, revalida manifesto e autorização e emite download R2 de 60 segundos. O hash do objeto gravado precisa corresponder ao SHA-256 reportado pelo worker. Originais preservados. Limites 20 MiB entrada, 24 MiB saída, 120 páginas e 40 arquivos; ainda não são limites do GoJus.

## Homologação sintética e reutilização
- /api/selftest gera internamente um PNG e um PDF e verifica a saída de duas páginas; sem R2, banco, documentos reais ou rede. Ativar FLIP_PDF_SELFTEST_ENABLED=1 apenas no projeto isolado flip-pdf-staging protegido por Vercel Authentication; desligar depois. Incompatível com o flag de processamento real. Não é prova de funcionamento do R2 nem do GoJus.
- O prefixo flip-pdf-temp/ permite uma única regra de expiração de 1 dia; cada empresa possui subpasta própria. Confirmar no painel Cloudflare ou API administrativa sem expor chaves. Se existirem objetos antigos em tenants/<tenant>/gojus-temp/, revisar separadamente; não criar regra de exclusão ampla tenants/.
- Para chamada entre projetos com proteção Vercel, preferir Trusted Sources/OIDC (autorizar somente projeto e ambiente de origem para o ambiente de destino) e manter token próprio da função. Alteração de controle de acesso requer aprovação explícita; não desabilitar proteção. O backend agora exige o token OIDC da requisição Vercel (x-vercel-oidc-token), encaminha-o exclusivamente ao endpoint HTTPS exato aprovado em GOJUS_PDF_WORKER_HOST (host .vercel.app) no header x-vercel-trusted-oidc-idp-token e exige também o token independente do worker. Sem identidade ou configuração válida, recusa antes de selecionar documentos. A verificação criptográfica OIDC é feita pela proteção da Vercel, não pelo parser de formato local. O fluxo ainda precisa de homologação real.
- Reutilizar pdf_bundle.py para outros clientes/tarefas específicas; cada tarefa futura precisa de autorização, escopo por empresa, limites, medição e revisão. Não é executor arbitrário de scripts ou navegador.
